# Native UI diagnostic capture

This development-only GPU fixture replaces the Application translation unit in a separate diagnostic link. It never adds exports to production, packages a Runtime, runs the original executable, or provides transport/full-playthrough acceptance. Captures use the actual GameSession, SDL/GLES renderer, original resources and Chromium SwiftShader.

Build the current requested production variants first. Their `build.json` source/header signatures must match the checkout; the diagnostic refuses stale caches, including headers that change class layouts. For ordinary builds the diagnostic reads `features.thprac` and requests matching `--thprac` flags; it does not change or overwrite that cache. For the focused MP audit use `--mp-only`, retaining the captured ordinary reference.

```sh
node portable/build.mjs --multiplayer
node portable/multiplayer/native-ui-build.mjs --phase standard-launcher --mp-only
node portable/multiplayer/native-ui-capture.mjs --phase standard-launcher --mp-only
```

`EMSDK` selects the pinned SDK. `EAGLER_LAUNCHER_ROOT` selects the Launcher checkout that provides Playwright. `TH11_TEST_ARCHIVE`, `TH11_TEST_FONTS` and `TH11_TEST_MUSIC_ROOT` can override the local retail archive, original baked font directory and decoded original music directory. Ordinary references load `th11_00.ogg` and `th11_01.ogg`; audio is muted and not part of screenshot acceptance. `--mp-only` builds/captures only MP and needs no music or ordinary binary; `--ordinary-only` captures just the ordinary references. Ordinary THPrac capture additionally requires the UI font used by its production build. All new diagnostic exports use the rejected-from-package `mp_fixture_ui_` prefix.

Outputs go to ignored `artifacts/multiplayer-ui/20261009/<phase>/`: diagnostic binaries, build signatures, screenshot evidence and PNGs. The initial `before` capture used commit `2bd03f0` and verified matching production cache signatures. Its captured source copies remain ignored artifacts, not checked-in test fixtures.

The MP fixture supplies exact native input arrays directly, then consumes native capture/text/audio events and draws/presents the real frame. Initial neutral ticks are 125. Life/Power fixtures set positions to x=0/10/100, y=400 and protect players from incidental bullets. Ghost rescue pins only ghost drift in this diagnostic, as recorded in evidence. Transfers themselves use native timing, input edges and items. Terminal screenshots enter existing StageExit seams; Ending runs the real Ending/Staff interpreter. They do not prove a full clear or the 180-frame wipe. Game Over/Extra/TitleResults settle for 30 ticks before capture. Whether original name registration appears depends on the one shared score qualifying for the in-memory native table.

The suite captures ordinary pause and Replay list, MP pause, three fresh local-seat views, three views of one prepared world, life gift hold 30/60/89/90 plus delivery, ghost rescue 45/89/90, Power taps 3/4/5, Game Over, Extra Result and post-Ending Results. Evidence records state/hash and the fixture entry alongside each PNG. HiScore and Score remain one native pair at their original positions. Only Life/Power repeat; each group starts with 1P/2P/3P, with the local heading in native yellow. Local Graze follows all seat groups at y=248 (2P) or y=320 (3P), with one blank row after the final Power row and no extra heading; point/communication retains its lower-left position. Pause retains all four native choices: Resume, Return, Replay Save and Restart. Replay Save uses the original confirmation, 25-slot list and name entry, then the existing all-seat Replay writer. Return retires the session, saves the partial Replay and uses the Launcher departure path to release the room. Restart requests the same confirmed generation fence as R. Result Continue/Retry remain unavailable and score files are never written.

`mp_fixture_ui_fixture(4)` prepares distinct resources once after the 125 neutral frames: lives 2/5/8, raw Power 20/36/60, Graze 111/222/333, point values 5000000/6000000/7000000, communication 2500/5000/10000 and two shared fragments. The driver then calls `mp_fixture_ui_local(0/1/2)` to draw three local perspectives of that same world, without a tick or restart. The export verifies unchanged canonical hash and frame; the driver independently compares them and checks actual queued native HUD text, positions, draw pass and heading colors through `mp_fixture_ui_hud()`. Expected lower-left text is `050000*0.26`, `060000*0.52`, `070000*1.03`. `localHud` in screenshot evidence records the three views and `mp-local-hud-1p.png` / `2p.png` / `3p.png` capture the actual renderer. The earlier `mp-3p-local1/2/3` shots are explicitly separate fresh beginnings, not the same-world proof. New captures use `standard-launcher`; historical `native-correction` artifacts remain intact.

## Native result and Replay Save I/O

`native-ui-save-capture.mjs` extends the MP capture with Game Over, Extra and Ending → native score registration → Replay slots → Replay name → save → Return/Back. Every action uses the real native directional, Shot and Pause inputs. It captures the score/name screen, native end choices where present, slots, and Replay name. The fixture links the current production `Application` scan, metadata and save methods, then decodes the actual saved files with `ReplayArchive::Load`; it does not fabricate a successful save response or write an ordinary Replay wrapper.

`mp_fixture_ui_record_io(0/1)` is an explicit diagnostic setup seam. The driver calls it immediately after native begin, before frame zero's first input, and then runs the 125 neutral birth frames. It appends inputs in the production ordering, including the save confirmation before servicing the file request. Native result scores and StageExit are controlled so the menu paths can be exercised. The score seam also prepares the native displayed/high counters with zero scroll speed: immediately injecting a large score and entering Game Over would otherwise freeze the original rolling HUD after only one update, producing a misleading discrepancy in the screenshot. Production scrolling and terminal freezing remain unchanged. End-choice screenshots wait 20 additional neutral frames for the original entrance animation. These files therefore prove the real menu/I/O/format integration, not gameplay replay determinism: the forced score and terminal transitions are absent from the input stream. The production fingerprint gate rejects their fixed diagnostic identity `[0x55494658, 0x54483131, 2, 1]`; timestamp is fixed at `1791504000`.

The save gate checks all three native terminal flows in live and read-only mode. It verifies one shared score, the native name, seat count, recorded seat, completion flag and confirmed save frame in decoded bytes. Read-only mode sets the actual `Netplay::BeginPlayback` ownership flag and compares every file's SHA256 before/after attempted manual and automatic saving. It does not claim spectator transport coverage.

The Game Over case first makes an automatic `PLAYER` backup, then uses the native menu to name that same slot `A`. The next automatic flush must select a different empty slot and preserve the named file byte-for-byte. Extra and Ending save to other selected slots; unrelated files must stay unchanged. The final gate verifies that `scoreth11.dat` does not exist.

`native-save-evidence.json` records these assertions, decoded headers and file hashes. `diagnostic-replays/` retains the exact diagnostic files for inspection. They stay under ignored artifacts with the screenshots, never in a production Runtime package. Keep historical `before`/`after` captures intact; `--phase` is only an output directory name and does not select an old source revision.
